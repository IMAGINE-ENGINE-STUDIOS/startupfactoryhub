# Project architecture rules
- APEX proposal licensing values live in src/pages/apex/licensing.ts with adjacent rule tests; why: displayed terms stay aligned with tested pricing without changing payment flows.
- Equity marketing artwork lives in src/components/marketing/EquityProgramBanner.tsx and equityBannerRenderer.ts, reusing the existing rover GLB and a shared Canvas/Three renderer for preview, GIF and JPG; why: animated exports and stills stay visually identical without remote rendering.

- Event participants pay only the displayed ticket price; the 5% platform fee is deducted from the organizer payout and is never shown on participant-facing event pages.

- AI credits live in user_ai_credits + ai_credit_ledger and change only through the service-role functions ai_credits_sync/consume/grant (idempotent by ledger ref); imagine-ai deducts per request and check-genius-plan grants monthly plan credits from active Stripe subscriptions; why: atomic, double-grant-safe billing without webhooks.
- AI uses _shared/ai.ts direct providers, never gateways; imagine-ai/providers.ts selects configured models, stream.ts streams with bounded continuation, and studio-genius authenticates first; why: protected keys and complete builds.
- Imagine Studio v2 (3D levels, locomotion, rig room, pushables) lives self-contained in src/imagine-studio/** (own pages, components, lib, index.ts), served at /imagine-studio, /imagine-studio/:id, /imagine-studio/rig-room, /locomotion, /level/:id, /levels; why: the heavy studio stays a separate solution while keeping the /imagine-studio URL every Imagine Engine wire uses.
- Imagine Studio heavy models get Nanite-style screen-space-error LOD from src/lib/nanite.ts (meshoptimizer), and heavy side panels load via lazyPanel in LevelEditorPage; why: keeps dense scenes and first load fast without removing features.
- Imagine Studio speaks the same __IE3D postMessage protocol as rt3d.js via src/imagine-studio/components/level/Imagine3DBridge.tsx (key ie-3d:studio3d, active only when embedded); why: Content-tab sliders and Flow 3D steps reach studio scenes without a second protocol.

- Imagine Engine runtime rules (bundle patches, ai.js, edit.js, blocks, live apps) live in public/imagine-engine/AGENTS.md; why: they only apply to that folder.- Live Video stage layout and host moderation live in src/components/live/LiveStage.tsx; room state (spotlight, audience mode, mic/camera requests) travels over the LiveKit data channel; why: no server-side room admin is needed and every viewer stays in sync.
- Live Video sales go through the live-checkout edge function: Startup Factory packages map to real Stripe price ids server-side (src/components/live/sfhPackages.ts mirrors them for display), host products are one-time payments; why: viewers can't change package prices and money lands in the platform Stripe account.
- Live Video guest check-ins are stored in live_guest_checkins (anyone can insert, only admins read); background effects run on the local camera track via @livekit/track-processors; why: guests need no account and everyone sees the same processed video.
- Live Video screen shares are published as LiveKit ScreenShare tracks and presented files are uploaded to the private live-shares bucket and broadcast as signed links (re-sent for late joiners); why: local-only streams and blob/data URLs never reach other participants.
- 3D Studio platform wiring (Sketchfab library, file drops, Genius 3D, Imagine Engine scene sync, publishing) lives in src/imagine-studio/components/level/StudioIntegrations.tsx; Genius 3D returns scene ops from the studio-genius function applied by lib/studioOps.ts, and published levels are public JSON written by studio-publish (plaza-district.json is admin-only and read by /plaza); why: no database migrations, and one component keeps the 5,900-line editor untouched.
- Plaza moderation (kick/mute/mute all/grant admin) and level elections go through the plaza-admin edge function: LiveKit RoomServiceClient for moderation, JSON in the studio-published bucket for granted admins and permanent election records; why: clients can't fake admin actions and no database migrations are possible.
- Public user pages (/u/:userId) store owner-chosen tabs, products/services and media in profile_sections/profile_listings/profile_media; purchases go through the profile-checkout edge function (price read server-side, paid to the platform Stripe account, 10% fee) and are recorded in profile_sales only by that function; why: buyers can't change prices and admins track every seller's sales in one table.
- Net groups live in net_groups/net_group_members/net_group_messages/net_group_events/net_group_invites with security-definer membership helpers; why: avoids recursive RLS on the members table.
- Brochure Studio (src/components/brochure-studio/**) is mounted once in App and edits any flipbook page it finds ([data-bp-root] or .stf__item); edits publish via the brochure-publish function to studio-published/brochures/<slug>.json and Studio-made brochures live at /b/:slug; why: one editor serves every existing and future brochure without per-page wiring.
- Investor Data Room (/data-room) lives in src/pages/InvestorDataRoom.tsx: documents in data_room_documents + private data-room bucket, viewers approved by email in data_room_access via can_view_data_room(); why: investors see diligence files only after an admin grants access.
